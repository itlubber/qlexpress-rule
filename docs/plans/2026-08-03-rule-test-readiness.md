# 规则测试准备流程实施计划

## 目标

让业务人员在执行规则前明确知道“规则是否加载成功、输入字段从哪里获得、当前是否处于降级状态、失败后如何恢复”，避免把接口失败误判为没有配置。

## 实施范围

1. 为项目与规则列表增加加载、失败、空结果和重试状态，不再静默吞掉请求异常。
2. 为测试输入建立 `未开始 / 加载中 / 已就绪 / 无结构化输入 / 加载失败` 状态，并展示字段数量、数据来源和降级原因。
3. 统一测试结构不可用时回退到规则输入字段；两条链路都失败时保留手工输入与重试通道。
4. 重新加载测试字段时按字段路径保留用户已经填写的值，避免重试清空业务样例。
5. 枚举选项、模型类型和追踪辅助信息失败时作为非阻断警告展示，不影响仍可执行的测试。
6. 项目、规则、输入结构和固定用例请求只允许最后一次响应更新页面，避免快速切换产生跨上下文覆盖。

## 验收标准

- 规则或项目列表请求失败时页面显示原因和重试按钮。
- 测试结构成功、回退成功、无入参、双链路失败四类状态均可区分。
- 回退或辅助元数据失败不会伪装成正常空状态，也不会无故阻止手工测试。
- 快速切换项目或规则时不会显示前一上下文的数据。
- 重新加载字段不会覆盖用户已填写的同路径参数值。
- 前端单测、lint、构建、Playwright 及真实浏览器流程通过；后端回归测试保持通过。
