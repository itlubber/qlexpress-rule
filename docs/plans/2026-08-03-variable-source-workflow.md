# 字段来源配置流程实施计划

## 目标

让业务人员按“归属与定义 → 取值方式 → 配置检查 → 提交审批”完成字段配置，并在审批前验证 API、数据库或名单取值；服务端必须阻止失效来源和跨项目错误引用。

## 实施范围

1. 新增字段来源兼容目录，仅返回全局资源与当前项目资源的必要摘要，不暴露连接或鉴权配置。
2. 新增字段草稿取值预览接口，复用正式运行时解析逻辑，不持久化草稿。
3. 在审批适配器中校验来源配置、来源状态和项目兼容性，并完整收集名单库 ID 依赖。
4. 将新建/编辑字段长表单改造成带进度检查、业务化来源卡片、分区配置和高级属性折叠的向导。
5. 在字段弹窗中提供审批前取值测试，清晰区分“测试取值”和“生成审批草稿”。

## 验证标准

- 项目字段只能选择全局或当前项目来源；全局字段只能选择全局来源。
- 切换范围或项目后重新加载来源目录，旧项目选择自动清理。
- 新建 API、数据库、名单字段无需先生成审批草稿即可执行取值测试。
- 来源缺失、停用或跨项目时，后端预览和审批预检均失败并返回可理解原因。
- 前后端单元测试、构建、lint、完整 Playwright 与真实浏览器流程全部通过。
