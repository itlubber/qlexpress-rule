# 数据库只读查询助手实施计划

## 目标

把需要手写 JSON 参数数组的数据库查询工具改成业务人员可以逐项填写的只读查询助手，并明确区分未执行、执行中、成功无数据、成功有数据和失败状态。

## 实施范围

1. SQL 中每个有效 `?` 占位符自动生成一个有顺序编号的参数行，忽略字符串和注释中的问号。
2. 参数行支持文本、数值、布尔和空值类型，前端按类型生成后端需要的参数数组。
3. SQL 修改时按占位符数量增减参数行，并保留仍然对应的已填写值。
4. 查询前校验单条只读 `SELECT`、禁止分号和锁定语句，与后端安全边界保持一致。
5. 查询结果区区分待执行、执行中、成功有数据、成功零行和失败，失败时保留 SQL 与参数供修正重试。
6. 同一页面快速切换数据源或重复查询时，只允许最后一次请求更新界面。

## 验收标准

- 业务人员不需要编写 JSON 即可完成带参数查询。
- 参数顺序、类型和值在界面上可直接核对，发送请求的数组顺序正确。
- SQL 中引号或注释里的 `?` 不会生成错误参数行。
- 非只读 SQL 在前端即被阻止，后端原有只读校验继续保留。
- 返回零行和查询失败不再显示为同一个空状态。
- 前端单测、lint、构建、Playwright、后端回归和真实浏览器查询通过。
