# 天枢决策引擎方案 A 实施总纲

## 1. 背景与目标

本轮改造针对四个已经通过代码审计和本地页面走查确认的问题：

1. 九类规则设计器的“临时保存、保存并编译、编译后测试”动作缺少统一层级、未保存保护和连续的发布前反馈。
2. 客户端 `L1MemoryCache` 的读取与写入共享同一把锁，高并发规则执行会产生不必要的读竞争。
3. `VariableSourceResolver` 顺序解析同一依赖层中的独立外部变量，多个慢源会累加延迟。
4. 项目缺少可重复运行的性能、容量、启动就绪和故障降级门禁。

目标是在不改变九类模型语义、不改变规则生命周期状态机、不改变变量按 ID 关联原则的前提下，降低配置误操作和运行延迟，并建立可持续执行的交付门禁。

## 2. 产品边界

- 一级菜单继续平铺，不分组、不引入“专家模式”。
- 直接 SQL 配置继续作为正常业务能力保留。本轮不隐藏、不弱化 SQL 编辑入口。
- 用户输入的变量编码、模型编码、脚本和导入字段原样保存，不做自动转换。
- 所有引用继续使用 ID；输出引用继续显式使用 `ref_type` 区分。
- 发布、审批和不可变制品继续使用现有治理体系，本轮只改善设计器到预检的衔接。

## 3. 子项目与顺序

| 顺序 | 子项目 | 独立验收结果 |
|---|---|---|
| 1 | 设计器统一操作与草稿安全 | 九类设计器共享同一操作层级、未保存保护、恢复副本和发布前检查反馈 |
| 2 | L1 缓存并发优化 | 缓存读取不再被全量快照或增量写入阻塞，快照与增量一致性保持不变 |
| 3 | 外部变量分层并行 | 同层独立外部变量有界并行，结果、异常策略、状态和追踪与顺序执行一致 |
| 4 | 运行质量门禁 | readiness、确定性并发测试、故障降级测试和可配置容量脚本可重复运行 |

四个子项目分别设计、测试和验证。前一个子项目失败不阻止后续子项目研究，但不得通过降低正确性断言来换取通过。

## 4. 总体验收原则

- 每个生产代码变更之前先新增能在旧实现上失败的测试。
- 前端变更通过单元测试、ESLint、生产构建、`dist` E2E，并使用本地前后端完成九类设计器中的代表流程验证。
- 后端和客户端变更通过模块测试、根目录全量测试、完整构建及服务启动验证。
- 并发优化必须同时证明结果一致性、追踪完整性、异常隔离和资源有界；只证明“更快”不算完成。
- 容量报告区分“本机测量值”和“产品保证值”，不得把一次开发机结果写成生产承诺。

## 5. 非目标

- 不重做规则治理状态机。
- 不重写九类编译器。
- 不引入新的规则表达式语法。
- 不在本轮重构所有超大型 Vue 文件，只抽取本次改造需要的共享边界。
- 不以本轮容量脚本替代真实部署环境的容量、备份恢复和灾备演练。
