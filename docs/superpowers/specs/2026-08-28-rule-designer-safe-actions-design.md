# 规则设计器统一操作与草稿安全设计

## 1. 目标

九类规则设计器使用同一套操作语义和视觉层级，让业务用户始终能回答三个问题：

1. 当前编辑内容是否已经保存？
2. 最新保存内容是否通过编译和发布前检查？
3. 下一步应该保存、修复问题、测试还是进入审批发布？

## 2. 当前问题

- 各设计器在各自模板内重复声明三个同权重按钮，文案还存在“配置/脚本”“编译/验证”的差异。
- `completeRuleCompile()` 成功后立即跳转生命周期页，用户无法在当前设计上下文中查看完整预检结果。
- `ruleDraftMixin` 已处理治理修订、乐观锁和只读历史版本，但没有客户端未保存状态。
- 路由切换、工作区页签切换、刷新和关闭浏览器不会统一提醒。
- 现有 `preflightRuleRevision()` 和 `RuleValidationReport` 只在规则详情页使用，设计器未复用。

## 3. 共享组件

新增 `RuleDesignerActionBar.vue`，由九类设计器共同使用。组件只负责展示和派发动作，不自行序列化模型或调用 API。

### 3.1 展示内容

- 左侧：规则版本选择、编辑状态、最近保存时间。
- 中部：编译与发布前检查摘要，显示错误数、警告数和可测试状态。
- 右侧：
  - 次级按钮：`仅保存草稿`。
  - 主按钮：`保存并检查`。
  - 后续按钮：`进入测试`，只有最新保存内容通过编译和预检后可用。
  - 文本入口：`查看生命周期`。

同一时刻只允许 `保存并检查`成为高对比主操作。错误和警告用图标加文字表达，不只依赖颜色。

### 3.2 状态机

| 状态 | 含义 | 主操作 |
|---|---|---|
| `CLEAN` | 当前内容与服务端草稿一致 | 保存并检查 |
| `DIRTY` | 存在未保存修改 | 保存并检查 |
| `SAVING` | 正在保存 | 禁止重复提交 |
| `SAVED_UNCHECKED` | 已保存但最新内容尚未完整检查 | 保存并检查 |
| `CHECK_FAILED` | 编译或预检存在阻塞项 | 修复后重新保存并检查 |
| `READY_TO_TEST` | 最新内容已保存且检查通过 | 进入测试 |
| `SAVE_CONFLICT` | 乐观锁冲突或草稿已被其他页面更新 | 重新加载或保留恢复副本 |

任何模型内容变化都清空上次预检通过状态并回到 `DIRTY`。

## 4. 设计器适配契约

扩展 `ruleDraftMixin`，约定每个设计器提供一个无副作用方法：

```js
serializeDesignerDraft()
```

该方法返回将提交给 `saveContent()` 的规范化 JSON 字符串。现有 `handleSave()` 改为复用该方法，禁止为脏状态检测执行修复、写入或弹窗等副作用。

共享 mixin 保存以下状态：

- `designerSavedFingerprint`
- `designerCurrentFingerprint`
- `designerSaveState`
- `designerLastSavedAt`
- `designerPreflightReport`
- `designerRecoveryAvailable`

内容加载完成后显式调用 `acceptDesignerBaseline()`；保存成功后以服务端返回修订中的 `modelJson` 更新基线。不能用整个 `$data` 比较，避免把面板展开、选中节点等纯 UI 状态误判为业务修改。

## 5. 保存与检查流程

### 5.1 仅保存草稿

1. 调用设计器现有本地校验。
2. 调用 `saveDraftModel()`。
3. 更新修订、锁版本和保存基线。
4. 清除恢复副本。
5. 状态进入 `SAVED_UNCHECKED`。
6. 不跳转页面，不运行发布前预检。

### 5.2 保存并检查

1. 执行“仅保存草稿”的全部步骤。
2. 若保存响应的 `compileSuccess` 为 `false`，展示编译问题并进入 `CHECK_FAILED`。
3. 编译成功后调用现有 `preflightRuleRevision(definitionId, revisionId)`。
4. 在设计器内使用现有 `RuleValidationReport` 展示报告。
5. `report.valid === true` 时进入 `READY_TO_TEST`，否则进入 `CHECK_FAILED`。
6. 不再从 `completeRuleCompile()` 自动跳转生命周期页。

### 5.3 进入测试

- 只有当前指纹等于最近检查通过指纹时可用。
- 点击后复用各设计器现有测试弹窗和参数模板。
- 测试不会隐式发布，也不会改变生命周期状态。

## 6. 未保存保护与恢复副本

### 6.1 路由和浏览器保护

- `beforeRouteLeave`：`DIRTY` 或 `SAVE_CONFLICT` 时显示“保存草稿 / 放弃修改 / 留在当前页”。
- 版本切换和工作区页签关闭走同一守卫。
- `beforeunload`：存在未保存修改时触发浏览器原生确认。
- `Ctrl+S`：在可编辑草稿中执行“仅保存草稿”；输入焦点位于 Monaco 时也保持该语义。

### 6.2 会话恢复

- 使用 `sessionStorage`，键为 `tianshu:designer-recovery:{definitionId}:{revisionId}`。
- 值只包含 `modelJson`、内容指纹、保存时间和基线 `lockVersion`。
- 修改后短延迟写入恢复副本；不向服务端自动保存。
- 重新加载同一修订时，只有恢复副本的基线锁版本与服务端一致才提示恢复。
- 用户显式选择恢复，不自动覆盖服务端内容。
- 保存成功、放弃修改、切换修订或修订锁版本不匹配时删除恢复副本。

使用 `sessionStorage` 而不是 `localStorage`，避免规则配置在浏览器长期残留。服务端自动保存不在本轮范围内，避免不完整配置频繁推进锁版本和编译流程。

## 7. 错误处理

- 本地序列化失败：保持 `DIRTY`，显示具体设计器错误，不调用服务端。
- 保存失败：保留恢复副本和当前编辑内容。
- 409 乐观锁冲突：进入 `SAVE_CONFLICT`，禁止继续测试；允许复制当前 JSON 或重新加载服务端草稿。
- 预检请求失败：保留已保存状态，标记“检查未完成”，不得宣称可测试或可发布。
- 只读历史修订：不注册保存快捷键，不生成恢复副本。

## 8. 测试与验收

### 8.1 共享单元测试

- 九类设计器都渲染共享操作栏，且只有一个主按钮。
- 内容变化后由 `CLEAN` 进入 `DIRTY`。
- 保存成功更新基线；再次触发相同内容不误报未保存。
- 编译失败不调用预检。
- 编译成功后调用预检并留在设计器。
- 修改已检查内容后立即禁用测试。
- 路由离开、页签关闭、`beforeunload` 和 `Ctrl+S` 行为一致。
- 恢复副本只在定义 ID、修订 ID 和锁版本全部一致时可恢复。

### 8.2 浏览器验收

至少覆盖决策表、决策流和 QL 脚本三个代表设计器，并确认其他六类通过 E2E 契约测试：

1. 修改后显示未保存状态。
2. 离开时出现保护提示。
3. 保存并检查后在原页面显示报告。
4. 检查通过后测试入口启用。
5. 再次修改后测试入口立即失效。
6. 刷新后可以选择恢复同一会话副本。

## 9. 非目标

- 不改变治理修订状态机。
- 不自动提交审批或发布。
- 不把九类设计器重写成单一巨型组件。
- 不持久化跨浏览器、跨设备的本地恢复副本。
