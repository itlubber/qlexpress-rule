# 分流实验执行助手设计

## 背景

当前分流实验列表的“执行”入口要求用户直接维护整段 JSON。页面虽然会请求实验测试 Schema，但只在 Schema 带样例时使用；请求失败会被静默忽略，并退回到一份与当前实验无关的固定税务/通信样例。业务人员无法判断字段从哪里来、当前是否可执行，也难以理解请求唯一键、进件时间、生产组与测试组结果之间的关系。

实验创建和详情页已经覆盖冠军组、挑战组、测试组、比例/条件分流、兜底动作和版本治理，本阶段不重写这些可用能力，只聚焦执行验证流程。

## 目标

- 默认让业务人员按字段填写实验入参，不要求理解 JSON。
- 保留 JSON 编辑作为高级入口，并保证两种模式切换时数据一致。
- 明确展示输入字段和样例的来源，以及加载、降级、失败状态。
- 让请求唯一键和进件时间的业务作用在填写位置可见。
- 把执行结果转成可读摘要，同时保留完整原始结果供排障。
- 防止快速切换实验、关闭弹窗或重复执行时，旧请求覆盖新状态。

## 不在本阶段范围

- 不修改初始数据快照中的数据库凭据处理方式。
- 不修改导航平铺及侧边栏拖拽折叠逻辑。
- 不改变实验路由算法、执行接口协议、日志写入逻辑或治理审批流程。
- 不在本阶段重做实验创建/详情编排页面。

## 交互设计

### 1. 打开执行助手

用户从实验列表点击“验证执行”。弹窗立即打开并显示“正在准备实验验证”，随后加载当前实验的测试 Schema。弹窗标题带实验名称或编码，减少误操作。

加载结果分为：

- `READY`：Schema 正常返回，字段和样例均可使用。
- `DEGRADED`：Schema 可用但没有字段，或加载失败；页面明确说明原因，并允许使用 JSON 高级模式继续验证。
- `ERROR`：初始化发生无法恢复的异常；页面展示错误和“重新加载”。

所有异步加载均绑定本次弹窗请求编号；弹窗关闭或切换实验后，旧响应不再更新页面。

### 2. 输入参数

默认进入“表单填写”：

- 数字使用数字输入框。
- 枚举使用下拉选择。
- 布尔使用 true/false 下拉。
- 日期使用日期选择器。
- 其他类型使用文本框。
- 字段名称作为次级提示，字段标签作为主标签。

“JSON 编辑”是高级入口。切换到 JSON 时从字段表单生成嵌套对象；切回表单时解析 JSON 并同步已识别字段。JSON 格式错误需要就地提示，并阻止执行。

Schema 样例优先用于初始值；无样例时按字段类型生成安全默认值。删除当前与实验无关的固定业务样例，避免误导。

### 3. 请求上下文

请求唯一键和进件时间置于独立的“分流上下文”区域：

- 请求唯一键：说明它影响稳定分流和测试组去重；为空时由后端按实验配置或常用入参路径解析。
- 进件时间：说明它用于判断测试组名单时点；可留空使用后端默认时间。

高级配置保持次要视觉层级，不与主入参竞争注意力。

### 4. 执行与结果

执行期间按钮进入加载状态并显示执行中提示。重复点击不会并发提交；弹窗关闭后旧执行结果不会回写。

结果区优先展示：

- 整体成功/失败与耗时。
- 实验追踪号和最终请求键。
- 生产命中组、规则、路由原因和执行状态。
- 各测试组的命中、跳过、成功/失败及耗时。
- 完整原始结果折叠展示，供技术排障。

请求失败统一转成可读错误结果，不依赖全局异常提示才能理解当前状态。

## 数据与状态设计

新增前端状态：

- `testLoadStatus`: `IDLE | LOADING | READY | DEGRADED | ERROR`
- `testLoadError`、`testLoadWarnings`
- `testFields`、`testParams`、`testMode`、`testJsonError`
- `testParamSource`: `SCHEMA_SAMPLE | FIELD_DEFAULTS | EMPTY`
- `testSetupRequestId`、`testExecutionRequestId`

继续使用现有 `normalizeTestSchema`、`schemaFieldsToTestFields`、`flattenSchemaSample`、`buildNestedSchemaParams` 和 `readParamPath`，不新增依赖，不改变后端协议。

## 验收标准

1. Schema 正常时，业务用户无需编辑 JSON 即可完成参数填写与执行。
2. Schema 无样例时，页面使用字段类型默认值并标明来源。
3. Schema 加载失败时不再静默，也不再出现固定税务/通信样例；用户能看见降级原因并使用 JSON 模式。
4. 表单与 JSON 双向切换保持嵌套参数一致，非法 JSON 阻止执行。
5. 执行请求包含 `params`、`requestKey`、`requestTime`，结果摘要正确反映生产组和测试组。
6. 快速切换实验、关闭弹窗、重复执行不会产生旧响应覆盖。
7. 单元测试、ESLint、构建、前端开发启动、后端编译/启动/测试、dist E2E、全栈 E2E 和真实浏览器 UI 验收全部通过。
