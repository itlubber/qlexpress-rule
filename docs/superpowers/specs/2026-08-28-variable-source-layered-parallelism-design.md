# 外部变量分层并行设计

## 1. 目标

在保持变量依赖、异常策略、来源状态、调用日志和追踪结果一致的前提下，并行解析同一依赖层中的独立 API、数据库和名单变量，降低多个慢源累加造成的规则执行延迟。

## 2. 范围

- 并行对象：`varSource` 为 `API`、`DB`、`LIST` 且在当前依赖层已经就绪的变量。
- 常量仍在解析开始前同步写入。
- 模型执行第一阶段保持确定性顺序；模型完成后可解锁下一层外部变量。
- 单变量在线预览继续使用同步路径，不进入线程池。

先不并行模型执行，可以避免把模型运行时线程安全、GPU/CPU 资源竞争和嵌套规则调用同时带入本次改造。

## 3. 依赖分层

保留现有依赖收集和必需字段展开逻辑。每轮执行：

1. 根据当前已解析名称选择所有就绪外部变量。
2. 为本层创建不可变 `resolvedParams` 快照。
3. 有界并行执行本层变量。
4. 等待本层全部完成。
5. 按变量原始定义顺序合并结果、来源状态和追踪事件。
6. 顺序执行当前已经就绪的模型。
7. 若本轮没有变量或模型推进，沿用现有循环依赖错误。

下一层不得读取正在执行层的部分结果。

## 4. 执行器

新增专用 `SourceResolutionExecutor`：

- JDK 17 `ThreadPoolExecutor`。
- 默认并行度 4。
- 有界队列。
- 饱和策略使用 `CallerRunsPolicy`，在过载时回退到调用线程并形成自然背压，不静默丢任务。
- 线程具有明确名称并在 Spring 容器关闭时主动停止。
- 通过 `rule-engine.source-resolution.parallelism` 配置并行度；值为 1 时等价于顺序执行。

正式把默认值设为 4 之前，必须先以并行度 1 建立基线，并满足第 9 节启用条件。

## 5. 任务输入与结果

每个任务只接收：

- 当前变量定义。
- 当前层开始时的不可变参数快照。
- 本次解析选项的只读副本。
- 本次调用级 API 单飞缓存。
- 当前运行时上下文快照。

每个任务返回 `SourceResolutionResult`：

- 变量 ID 和脚本名称。
- 最终值，包括默认值或异常策略结果。
- 独立的来源状态映射。
- 独立的追踪事件列表。
- 需要写入的调用日志结果。

工作线程不得直接写共享 `LinkedHashMap`、共享 `VariableResolveOptions.sourceStates` 或父追踪帧事件列表。

## 6. 运行时上下文传播

`RuntimeContextBridge` 当前使用 `ThreadLocal`。新增最小上下文快照能力，捕获当前规则元数据和匹配条件；工作线程绑定该只读上下文，并把追踪事件写入任务本地列表。

任务完成后：

1. 工作线程清理所有桥接上下文，防止线程复用污染。
2. 调用线程按稳定顺序把本地追踪事件重新提交给原追踪监听器。
3. 调用线程合并来源状态。

不允许多个工作线程直接向 `RuleTraceFrame.getEvents()` 返回的普通列表并发追加。

## 7. 同请求 API 单飞缓存

当前 `apiResponseCache` 是 `LinkedHashMap`。并行后替换为本次解析调用级的单飞缓存：

- 键继续使用 `apiConfigId + 请求参数 JSON`。
- 值使用 `CompletableFuture<Map<String, Object>>`。
- 第一个任务实际调用外数，其余相同请求等待同一个结果。
- 失败完成后移除失败项，异常策略仍由每个变量独立应用。

该缓存只在一次规则解析调用内存在，不改变现有跨请求缓存策略。

## 8. 超时、异常和降级

- 外数、数据库和名单调用继续使用各自已有超时。
- 任务异常先进入现有变量异常策略；有默认值或忽略策略时返回正常结果。
- 不允许单个变量失败取消同层其他变量。
- 调用线程被中断时取消尚未开始的任务，恢复中断标志并结束本次规则执行。
- 队列饱和时由调用线程执行任务，不创建无界线程。

## 9. 基准与启用条件

实现顺序：

1. 使用并行度 1 运行固定夹具，记录顺序基线。
2. 使用并行度 4 运行相同夹具。
3. 比较输出参数、来源状态、调用次数、异常策略和追踪事件。
4. 测量 1、2、4、8 个独立慢源的总耗时和 P95。

默认并行度从 1 调整为 4 必须同时满足：

- 所有正确性和追踪一致性测试通过。
- 4 个独立慢源相对顺序基线的中位耗时至少降低 20%。
- 无线程泄漏、无无界队列增长、无额外外数重复调用。
- 依赖链场景仍严格按层执行。

若性能收益未达到条件，保留实现但默认并行度保持 1，并在报告中说明原因，不通过降低断言强行启用。

## 10. 测试

- 两个独立源通过屏障证明实际并发启动。
- 下游变量在上游完成前不能启动。
- 同一 API 和相同参数只调用一次。
- 合并顺序与变量定义顺序一致。
- 默认值、返回空、超时、异常、熔断和名单无匹配行为与顺序执行一致。
- 来源状态和追踪事件完整且顺序稳定。
- 并行度 1 与旧顺序结果完全一致。
- 执行器关闭后没有存活的专用线程。

## 11. 非目标

- 不并行执行模型、QL 脚本或嵌套规则。
- 不修改数据库连接池或外数 HTTP 连接池容量。
- 不改变变量依赖表达式和参数映射语法。
- 不以增加线程数规避单个来源本身的超时或性能问题。
