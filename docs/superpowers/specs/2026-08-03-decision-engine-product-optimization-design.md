# 天枢决策引擎产品优化设计

日期：2026-08-03

## 1. 目标

在不改变现有技术栈、九类规则设计器、稳定 ID 引用规则和一级菜单布局的前提下，修复影响规则正确性和共享资源安全的流程缺陷，并将项目配置、审批、外数配置和运行验证组织为业务人员能够理解和完成的连续流程。

本次优化采用纵向切片交付。每个切片必须同时完成后端、前端、自动化测试和真实浏览器验收，验证通过后才能进入下一切片。

## 2. 明确不在范围内

- 不处理初始数据快照中的明文数据库凭据。
- 不改变一级菜单平铺方式。
- 不增加侧栏收起按钮；继续使用拖拽宽度触发自动折叠或展开。
- 不替换 Vue、Element Plus、Spring Boot、MyBatis Plus、QLExpress 等现有技术栈。
- 不修改用户填写的变量编码、模型编码、导入字段名称或其他业务标识。

## 3. 设计原则

1. 所有变量、模型、规则、项目和数据对象关联继续使用稳定 ID。
2. 输出字段继续通过 `ref_type` 明确区分变量和模型，不根据 ID 值猜测。
3. 受治理配置在审批通过前不得修改生效投影表。
4. 旧数据优先兼容读取，不自动创建草稿、不隐式迁移、不覆盖历史内容。
5. 项目上下文只负责筛选和表单默认值，不作为权限边界；后端仍独立校验权限和资源归属。
6. UI 优先展示业务动作、资源名称和影响结果，内部路径与 ID 作为次要诊断信息。
7. 只拆分本次实际触及的复杂页面，不进行无关重写、格式化或框架替换。

## 4. 交付切片

### 4.1 切片一：历史规则查看与项目规则关联

#### 历史规则只读展示

- 当规则没有任何治理修订时，`ruleDraftMixin` 调用现有规则内容接口读取 `modelJson`。
- 前端构造仅用于展示的历史内容视图，状态固定为只读历史状态，不持久化到后端。
- 九类设计器继续只消费统一的 `viewRevision.modelJson`，不分别实现兼容逻辑。
- 历史内容视图禁止保存、编译、测试和任何可能生成草稿的操作。
- 页面明确说明当前展示的是历史生效内容，需要修改时必须前往生命周期页面显式创建治理草稿。
- 指定修订来源加载失败时仍保持失败，不得悄悄回退到其他版本。

#### 项目内全局规则关联

- 为项目与全局规则的关联建立独立治理资源 `RULE_PROJECT_BINDING`。
- 关联快照只保存关联记录 ID、项目 ID、规则 ID 和必要的展示摘要；关联关系仍通过 ID 建立。
- “添加全局规则”只创建审批草稿，审批通过后才写入 `rule_definition_ref`。
- 项目中的全局规则显示“移出项目”，不显示会删除共享规则的“删除”。
- “移出项目”创建删除关联审批草稿，审批通过后才删除关联记录。
- 项目级规则的删除仍走规则删除审批，并显示“删除审批草稿已创建”后跳转审批详情。
- 关联审批归入审批中心的“规则”类别。

### 4.2 切片二：补齐决策相关治理

#### 名单库元数据

- 增加 `LIST_LIBRARY` 治理资源适配器。
- 名单库新增、修改、启用、停用和删除在审批通过前不改变生效名单库。
- 删除和停用必须执行变量引用及规则影响检查。

#### 名单记录批次

- 名单记录的单条新增、修改和删除统一转换为一条记录的批次变更。
- 导入文件生成批次草稿和暂存记录，审批前不修改 `rule_list_record`。
- 批次保存新增、更新、删除、重复、无效和总记录数，以及内容摘要。
- 审批通过时在一个事务内应用整个批次；任一写入失败则全部回滚。
- 审批取消、驳回或冲突时清理或封存暂存数据，不影响生效记录。
- 审批页面展示批次摘要和有限样例，不将全部名单内容写入审批 JSON。

#### 其他运行配置

- 增加 `FIELD_VALIDATION` 治理资源，覆盖字段校验规则新增、修改、启停和删除。
- 增加 `BILLING_CONFIG` 治理资源，覆盖计费配置新增、修改、启停和删除。
- 项目鉴权密钥轮换保持即时操作和审计，不纳入本次审批，避免安全事件下无法及时轮换。

### 4.3 切片三：项目工作台与项目上下文

#### 项目工作台

- 将现有项目详情升级为项目工作台，同时保留项目规则列表能力。
- 后端提供项目就绪度聚合接口，返回项目生效状态、字段数量、数据来源状态、规则草稿和发布数量、测试用例数量、待审批数量、最近执行摘要。
- 工作台以动态检查清单替换静态八步说明，每一步包含状态、阻塞原因和可点击下一步。
- 工作台提供变量、数据源、模型、规则、测试、审批和日志快捷入口，不改变一级菜单。

#### 项目上下文

- 新增前端项目上下文状态，保存当前项目 ID 和基本展示信息。
- 从项目工作台进入模块时通过路由查询参数显式携带项目 ID，并同步到上下文。
- 模块页面顶部展示当前项目，可切换项目或退出项目上下文。
- 项目上下文存在时，新建项目级资源默认使用该项目，但仍允许用户明确改为全局资源。
- 项目上下文不存在时，规则、变量和实验的新建表单不得默认全局或默认第一个项目，必须明确选择作用范围和项目。
- 所有后端查询继续显式接收 `projectId`，不得依赖浏览器状态推断项目。

### 4.4 切片四：审批任务中心

#### 任务视图

- 审批首页提供“待我审批”“我的申请”“全部记录”三个主视图。
- 默认打开“待我审批”；资源类别作为筛选条件，不再默认限定字段类别。
- 后端查询根据当前操作人和视图类型过滤，前端不得自行伪造申请人或审批人条件。

#### 草稿继续编辑

- 编辑中审批单显示“继续编辑”。
- 前端根据资源类型映射回原业务页面，并携带 `approvalId`。
- 原业务页面读取审批草稿快照填充现有表单，保存时调用 `saveGovernanceDraft` 更新同一申请。
- 不允许因为继续编辑而创建第二条活动申请。
- 待审批、已通过、已驳回、已取消和冲突申请均不可继续修改。

#### 业务化差异

- 建立资源类型到业务字段标签的集中映射。
- 差异优先显示字段名称、旧值、新值和业务影响；JSON 路径仅作为辅助信息。
- 依赖优先显示资源名称、项目和引用位置，资源 ID 作为辅助信息。
- 敏感字段只显示“已变更”，不得回显原值或新值。
- 预检失败、冲突、驳回和取消状态提供明确的处理建议和返回入口。

### 4.5 切片五：外数 API 渐进式配置

- 保持现有保存字段和后端协议不变，将页面主流程重组为“基础信息”“请求映射”“响应与测试”三个步骤。
- 鉴权、连接流控、脚本、异常重试、缓存和计费放入高级配置。
- `NONE` 鉴权隐藏 Token 缓存和刷新配置；`INHERIT` 只展示继承说明。
- 只有异步请求显示轮询、回调和异步结果配置。
- 普通字段映射优先使用行式可视化编辑；JSON 和脚本编辑作为高级能力保留。
- 每一步显示完成状态、缺失字段和阻塞原因。
- 保存前按步骤校验，错误必须定位到对应步骤和字段。
- 页面拆分为基础、鉴权、请求、响应、高级和测试组件，父页面只负责加载、组装、保存和路由离开保护。

### 4.6 切片六：复杂页面拆分与完整 E2E

- `VariableList.vue` 分离列表编排、变量表单、来源配置、导入和字段校验组件。
- `ApiDetail.vue` 按切片五的步骤拆分。
- `TraceTree.vue` 分离纯数据转换、筛选、节点渲染和详情展示。
- 组件拆分不得改变 API 请求、持久化字段、稳定 ID 或用户输入内容。
- 新增真实全链路 Playwright 场景：项目工作台、字段配置、规则设计、规则测试、审批、生效、调用和执行日志。

## 5. 数据流

### 5.1 普通治理资源

业务表单 → 创建或更新治理草稿 → 依赖预检 → 提交审批 → 审批通过 → 事务更新生效投影和不可变版本 → 页面重新加载生效数据。

### 5.2 名单批次

文件或单条操作 → 校验并写入暂存批次 → 创建治理草稿 → 展示批次摘要 → 提交审批 → 审批通过后事务应用全部记录 → 记录批次结果和名单日志。

### 5.3 历史规则

查询治理修订为空 → 读取现有规则内容 → 构造前端只读历史视图 → 设计器展示 → 用户显式前往生命周期创建草稿后才能修改。

## 6. 错误处理

- 旧规则内容不存在或 JSON 无法解析时展示明确错误，不展示空白设计器冒充真实内容。
- 关联审批检测项目、规则或关联记录已经变化时进入冲突状态，不覆盖新数据。
- 名单批次在校验阶段报告行号和原因；应用阶段失败则完整回滚。
- 项目就绪度聚合的单个非关键统计失败时返回该检查项失败状态，不使整个工作台不可用。
- 项目上下文与资源实际项目不一致时以后端资源归属为准，并提示用户切换上下文。
- 审批草稿编辑页面发现状态已经变化时终止保存并刷新审批状态。

## 7. 测试与验收

每个切片都执行以下流程：

1. 先新增能够复现问题或表达需求的失败测试。
2. 完成最小实现，使新增测试通过。
3. 复核稳定 ID、`ref_type`、原始编码保留和审批前不改变生效数据。
4. 前端执行 ESLint、构建和全部 Vitest 测试。
5. 后端执行 `mvn clean install -DskipTests`、启动 `rule-engine-server`、HTTP 健康验证和全部 Maven 测试。
6. 长期验证服务使用 1800000ms 工具超时，并在验证后主动停止本轮创建的进程。
7. 使用独立验证端口，避免停止或覆盖用户已有的 8080、9090 服务。
8. 浏览器通过真实 UI 完成创建、编辑、送审、审批、生效和结果检查，不通过后端接口直接造数据跳过业务步骤。
9. 每个切片完成代码自检和差异审查后才能开始下一切片。

## 8. 完成标准

- 九类设计器能够正确展示没有治理修订的历史规则内容。
- 项目内共享规则只能移出项目，不能被误认为项目私有规则删除。
- 名单、字段校验、计费和项目规则关联在审批通过前不改变生效配置。
- 业务人员从项目工作台进入各模块时项目范围保持一致，不会意外创建全局资源或落入错误项目。
- 审批人进入页面即可看到待办，申请人能够继续编辑自己的编辑中草稿。
- 审批差异以业务字段和影响为主，内部路径仅作辅助。
- 外数 API 的常用同步接口可以在三个主步骤内完成，高级配置不会干扰基础流程。
- 前后端全量测试通过，真实浏览器主链路验收通过。
