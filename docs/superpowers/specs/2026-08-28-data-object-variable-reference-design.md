# 数据对象表格与字段引用变量设计

## 目标

- 变量管理中的数据对象改为与变量列表一致的表格布局，每行展示一个数据对象。
- 数据对象行可展开，展开区继续展示该对象的字段树和字段操作。
- 数据对象字段可通过稳定 ID 直接引用普通变量。
- 规则使用已配置引用的数据对象字段时，调用方可传入引用变量，引擎自动把变量值装配到数据对象字段路径。
- 数据对象字段映射、变量依赖和发布制品保持可验证、可追踪且版本不可变。

## 非目标

- 不改变一级菜单结构、数据对象导入方式或现有审批流程。
- 不通过变量编码、名称或脚本名称回溯引用关系。
- 不对列表元素内的单个子字段做隐式按索引拼装；LIST 字段可整体引用 LIST 变量。
- 不把字段引用变量扩展为任意表达式、字段转换器或多变量聚合。

## 已确认语义

假设数据对象 `request` 的字段 `age` 引用变量 `age`：

- 仅传 `{"age": 22}` 时，引擎自动得到 `request.age = 22`。
- 同时传 `{"age": 22, "request": {"age": 30}}` 时，`request.age` 保持为 `30`。
- 目标路径显式值优先；引用变量只在目标路径缺失时补位。
- 多个数据对象字段可以引用同一个变量，并分别装配到各自路径。
- API、数据库、名单等来源变量按原有解析逻辑得到值后，也可装配到目标字段。
- 引用值缺失、无效或类型不兼容时，沿用规则输入缺失值、字段校验和执行错误语义，不静默伪造默认值。

## 方案选择

采用“数据对象字段元数据绑定 + 运行时装配 + 制品冻结”方案。

不采用把映射复制到每条规则的方案，因为同一数据对象会产生重复配置和版本漂移。不采用按编码自动匹配的方案，因为变量编码可修改，且项目要求所有引用关联必须通过 ID。

## 数据模型

在 `rule_data_object_field` 增加可空字段：

- `ref_variable_id BIGINT NULL`：直接引用的 `rule_variable.id`。
- 索引 `idx_ref_variable_id`：支持影响分析和依赖查询。

`ref_variable_id` 与现有 `ref_object_id` 职责不同：

- `ref_object_id` 描述 OBJECT/LIST 字段的结构来源。
- `ref_variable_id` 描述执行时该字段的值来源。
- OBJECT/LIST 字段可以同时配置两者：前者约束结构，后者提供整个字段值。

实体、审批聚合快照、导入导出和数据库兼容同步逻辑均携带 `refVariableId`。不保存引用变量的编码或脚本名作为关联依据；展示信息由 ID 实时查询，发布信息由制品冻结。

## 管理端交互

数据对象页签使用 `el-table`：

- 每行一个数据对象。
- 列包含作用范围、项目名称、对象编码、对象名称、脚本名称、对象类型、来源、字段数、状态/更新时间和操作。
- 使用展开列打开字段区域；展开状态只属于当前页面，不改变后端数据。
- 字段区域保留树形层级、枚举选项、编辑、删除和分页能力。

字段表新增“引用变量”列。字段编辑弹窗新增可清空、可搜索的引用变量选择器，候选项展示变量名称、编码、类型和来源。选择后保存 `refVariableId`；清空后解除映射。

原“引用对象”配置仅在 OBJECT/LIST 字段显示，并在界面文案中明确为结构引用，避免与“引用变量”混淆。

## 保存与审批校验

数据对象审批草稿校验以下条件：

- 引用变量存在且已启用。
- 全局数据对象只能引用全局变量；项目级数据对象可引用同项目变量或全局变量。
- 数据对象字段类型与引用变量类型兼容；数值家族按现有类型兼容规则处理，其余类型要求一致。
- 列表元素内部的子字段不得配置直接引用变量；应在 LIST 字段上整体引用 LIST 变量。
- 删除、停用或转全局操作继续通过既有影响分析与审批流程，并把字段引用关系计入影响范围。

校验失败时阻止审批生效，并返回包含对象、字段和变量信息的明确错误消息。

## 规则输入投影

规则字段分析遇到 `DATA_OBJECT` 字段时：

- 未配置 `refVariableId`：保持现状，规则输入仍是数据对象字段路径。
- 已配置 `refVariableId`：把引用变量作为真实上游依赖继续展开。
- INPUT 变量成为调用方可直接传入的平铺输入。
- API、DB、LIST 等变量继续展开其依赖，同时保留运行时来源变量供解析和装配。
- 数据对象目标路径不再作为必填调用参数展示，但仍保留为允许显式覆盖的兼容输入。

规则测试参数模板、接口文档和输入 Schema 使用展开后的真实调用方输入，避免界面仍要求填写已经被变量映射替代的对象字段。

## 运行时数据流

新增独立的数据对象字段引用装配服务，复用统一的路径读取、写入和类型转换规则：

1. 根据规则输入和直接模型引用收集实际使用的数据对象字段。
2. 加载这些字段的 `refVariableId` 映射及对应变量元数据。
3. 记录调用方原始参数中已显式存在的目标路径。
4. 执行现有参数绑定和变量来源解析。
5. 对未显式传入的目标路径，从引用变量脚本路径读取最终值并写入数据对象路径。
6. 按数据对象字段类型转换装配值，再执行字段校验和 QLExpress。

优先级固定为：显式目标路径 > 引用变量最终值 > 现有缺失值处理。是否存在以路径键是否存在为准；显式 `null` 也属于显式目标值，不被引用变量覆盖。

活动规则和发布制品执行使用同一装配入口。规则调用、实验执行和规则测试复用该入口，不分别实现映射逻辑。

## 发布制品与兼容性

规则依赖闭包在发现数据对象字段引用变量后：

- 把 `refVariableId` 写入数据对象字段组件快照。
- 把引用变量及其外部来源依赖加入制品依赖闭包。
- 运行时从制品读取冻结的数据对象字段映射，不查询后来修改的在线配置。

历史制品没有 `refVariableId` 时按未配置映射处理，保持原行为。新增数据库列允许为空，不需要回填历史数据。

## 错误处理

- 保存或发布时发现引用不存在、越权、停用或类型不兼容：阻止操作并返回治理校验错误。
- 活动配置在执行时异常缺失：返回明确的稳定引用错误，不按名称降级查询。
- 引用变量最终没有值且目标路径也未显式传入：按该字段现有缺失值和校验规则处理。
- 变量解析失败：沿用变量的异常策略和来源状态记录；装配层不吞掉异常。
- 目标路径中间节点不是对象：返回包含目标路径的参数类型错误，不覆盖调用方数据。

## 测试与验收

后端先增加失败测试，再实现：

- 字段引用保存、审批校验、作用域和类型兼容测试。
- 规则输入从数据对象字段展开为引用变量的测试。
- 仅传引用变量时自动装配、同时传入时目标路径优先、显式 `null` 优先测试。
- 外部来源变量解析后装配、多字段引用同一变量、缺失值和非法中间路径测试。
- 制品依赖闭包、快照加载和历史制品兼容测试。
- 规则测试、正式执行、实验和嵌套规则入口的一致性测试。

前端先增加失败测试，再实现：

- 数据对象每行一个并可展开字段表。
- 数据对象列、字段计数、状态、更新时间和操作展示。
- 字段引用变量选择、回显、清空、类型过滤和提交载荷。
- 与当前工作区中“脚本名称只在编辑弹窗修改”的既有改动兼容，不恢复行内失焦保存。

完成后执行项目规定的前后端编译、启动和完整测试；前端额外运行 ESLint，并通过浏览器从变量管理创建/编辑数据对象、配置引用、审批生效、规则测试传参到执行结果完成真实 UI 验收。所有长期服务使用 30 分钟工具超时并在验证后主动停止。
