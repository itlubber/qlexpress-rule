# 性能、容量、启动就绪与故障降级门禁设计

## 1. 目标

建立可重复、可解释、可分层运行的质量门禁，使以下问题在发布前可被发现：

- 应用端口已监听，但关键依赖或要求预热的模型尚未就绪。
- 缓存或变量解析并发改动造成性能回退。
- 外数、数据库、Redis 或模型运行时异常时，既定降级策略失效。
- 容量测试只有人工命令，没有结构化结果和统一判定。

## 2. 三层门禁

### 2.1 CI 确定性门禁

每次提交运行，不依赖开发机绝对速度：

- L1 缓存并发一致性。
- 外部变量依赖层、并发屏障、单飞和结果一致性。
- 外数超时、熔断、陈旧缓存和默认值策略。
- 数据库异常和名单无匹配策略。
- ONNX GPU 不可用时回退 CPU。
- readiness 状态转换。

### 2.2 本地/预发布性能门禁

运行固定夹具并输出结构化 JSON：

- 缓存命中吞吐和并发读取延迟。
- 外部变量顺序与并行耗时对比。
- 规则执行吞吐、P50、P95、P99、错误率和超时率。

默认使用相对回退阈值；机器相关的绝对吞吐只作为本次运行记录。

### 2.3 部署环境容量门禁

使用真实部署配置和显式测试项目运行。阈值由部署环境提供，报告必须包含：

- 测试时间、并发数、总请求数。
- 成功、业务失败、系统失败和超时数量。
- 吞吐量、P50、P95、P99、最大耗时。
- 服务版本、JDK、CPU、内存和配置摘要。
- 最终通过/失败及具体阈值差距。

## 3. 标准启动就绪

引入 Spring Boot Actuator，仅暴露：

- `/actuator/health/liveness`
- `/actuator/health/readiness`

readiness 组包含：

- 数据库健康。
- Redis 健康。
- `OnnxWarmupHealthIndicator`。

`OnnxModelWarmupRunner` 维护明确状态：

- `NOT_STARTED`
- `WARMING`
- `READY`
- `FAILED`

没有要求预热的启用 ONNX 模型时直接 `READY`。要求预热的模型全部成功后才 `READY`；任一预热失败时 readiness 返回 `OUT_OF_SERVICE` 并列出失败模型编码。CUDA 不可用但成功回退 CPU 视为成功，同时在详情中标明实际执行提供者。

liveness 不依赖数据库、Redis 或模型预热，避免依赖故障触发无意义的进程重启。

## 4. 容量脚本

新增基于 Node.js 20 内置 `fetch` 的脚本，不增加压测依赖。脚本：

- 只调用用户显式指定的本地或预发布规则执行地址。
- 从环境变量读取鉴权和阈值，不把凭据写入命令输出或报告。
- 支持预热阶段、固定持续时间、固定并发和请求超时。
- 报告写入 `target/quality-gates/`。
- 失败时退出码非零。

必要配置：目标 URL、测试请求文件、并发数、持续时间、超时、最大错误率、最大 P95。未提供生产阈值时只生成报告，不宣称通过生产容量要求。

## 5. 故障降级矩阵

| 故障 | 期望行为 | 门禁证据 |
|---|---|---|
| 外数连接超时 | 按变量异常策略返回默认值、空值或失败 | 输出、来源状态、调用日志、追踪 |
| 外数连续失败 | 熔断器打开，后续调用快速失败或使用陈旧缓存 | 调用次数和状态转换 |
| Redis 不可用 | 不破坏进程内允许的缓存读取；需要 Redis 的同步能力明确降级 | 健康状态和缓存行为 |
| 数据库查询超时 | 连接归还池，变量按策略降级 | 池状态、输出和日志 |
| 名单无匹配 | 返回配置语义对应结果，不视为系统异常 | 输出和来源状态 |
| CUDA 不可用 | 配置允许时回退 CPU，readiness 反映实际提供者 | 模型执行结果和健康详情 |
| ONNX 必需模型预热失败 | readiness 拒绝流量，liveness 保持存活 | 两个健康端点状态 |

## 6. CI 集成

- 现有 `mvn test`、`npm test`、ESLint、构建和 `dist` E2E 保持不变。
- 后端 CI 增加命名清晰的可靠性门禁步骤，运行确定性测试集合并上传测试报告。
- 容量脚本不在普通 PR CI 使用绝对阈值，避免共享 Runner 抖动造成误报。
- 发布流水线或人工预发布验收使用环境阈值运行容量门禁。

## 7. 安全和数据边界

- 健康端点不得返回密码、Token、SQL、连接串或模型内容。
- 容量脚本默认不记录完整请求和响应，只记录状态、耗时和错误分类。
- 容量测试必须使用显式测试项目，禁止自动选择生产规则。
- 脚本不会创建、修改、审批或发布控制台配置。

## 8. 验收

- 进程启动到端口监听期间 readiness 不是 `UP`，关键依赖和模型预热完成后变为 `UP`。
- 必需模型预热失败时 readiness 为 `OUT_OF_SERVICE`，liveness 仍为 `UP`。
- 故障矩阵每一行都有自动化测试，且断言包含业务输出和可观测状态。
- 性能和容量脚本在相同参数下可重复运行并生成结构固定的 JSON 报告。
- CI 能明确区分功能测试失败、可靠性门禁失败和容量阈值失败。

## 9. 非目标

- 不在本轮建设持续压测平台或可视化性能中心。
- 不承诺未经真实部署环境验证的生产 QPS。
- 不用 readiness 替代监控告警。
- 不让 liveness 因外部依赖短暂故障而失败。
