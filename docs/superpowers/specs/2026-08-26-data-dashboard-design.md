# 天枢决策引擎数据看板设计

## 1. 背景与目标

天枢决策引擎当前以“项目管理”作为控制台默认进入页。新增“数据看板”后，控制台默认进入 `/dashboard`，项目管理继续作为独立、平铺的一级菜单保留。

数据看板从现有权威数据表自动计算业务、运行、计费和治理指标，不建立需要人工维护的业务进件表。首期数据来源为：

- `rule_execution_log`：进件、决策、金额、期数、设备、经纬度、规则执行耗时和规则集追踪；
- `rule_runtime_call_log`：数据库查询、名单匹配和上游外数 API 调用次数、查得情况及耗时；
- `rule_billing_record`：计费请求及计费金额；
- `rule_db_datasource`、`rule_external_datasource`、`rule_external_api_config`、`rule_list_library`：资源数量及分类；
- `rule_definition`、`rule_definition_ref`：项目规则数量；
- `governance_approval_request`：规则审批状态分布。

看板必须满足以下目标：

1. 默认统计从当前日期前 6 天的 `00:00:00` 到查询时刻，允许今日、近 7 天、近 30 天和跨度不超过 90×24 小时的自定义时间范围；
2. 支持全部项目或单个项目筛选，仅统计当前账户现有模块权限允许查看的内容；
3. 筛选条件只保存在当前浏览器会话，不跨浏览器会话或登录持久化；
4. 字段映射支持“用户项目覆盖 → 用户默认 → 系统默认”逐字段回落；
5. 原始日志不可变。看板不得更新、清洗或删除任何日志原文；
6. 针对真实查询形态验证并补充数据库索引，不凭猜测增加重复索引；
7. 页面采用现有主题、筛选区、空状态和响应式布局规范。

## 2. 非目标

- 不新增项目级数据权限模型。首期沿用现有模块级 RBAC；
- 不把项目管理折叠到数据看板，也不改变其他一级菜单的平铺结构；
- 不建立按用户预计算的永久统计汇总表；
- 不修改变量编码、变量名称、脚本名称或用户导入内容；
- 不调用外部地图服务，不上传经纬度或其他进件数据；
- 不把无效经纬度从日志表删除或改写。

## 3. 总体架构

采用“后端按需聚合 + 前端分区并行加载 + 查询索引优化”的方案。

前端并行请求三个相互独立的统计分区：

1. 进件分析：核心决策指标、期数占比、金额占比、设备数和地图热力图；
2. 运行资源：规则执行耗时、数据库/名单/外数资源及查询时效、账单调用；
3. 规则治理：规则集 TOP 命中和规则审批状态分布。

单个分区加载失败时，其他分区继续展示。每个响应携带服务端实际使用的统计起止时间、项目范围、映射来源和权限裁剪结果，便于前端说明口径。

业务字段由后端在查询时从 `input_params` 或 `output_result` 提取。动态 JSON 路径只能由经过校验的字段引用生成，客户端不能提交任意 SQL 或任意 JSONPath。

## 4. 路由与导航

- 新增 `/dashboard`，名称为“数据看板”，放在侧栏第一项；
- 根路由 `/`、登录成功默认回跳、无权限回退、关闭全部工作区页签后的兜底路径统一改为 `/dashboard`；
- `/project` 继续作为“项目管理”一级菜单；
- 新增 `/dashboard/settings`，名称为“数据看板设置”；
- `/dashboard` 支持现有项目上下文。当 URL 显式包含 `projectId` 时优先使用该项目，否则恢复本次会话上次使用的看板筛选；
- 页面筛选使用 `pageStateCache` 和 `sessionStorage`，不写入用户偏好表。

## 5. 字段映射

### 5.1 映射字段

设置页支持以下字段：

| 角色 | 系统默认引用 | 默认 JSON 来源 |
|---|---:|---|
| 进件编号 | `rule_variable.id = 3` (`request_id`) | INPUT |
| 设备号 | `rule_variable.id = 14` (`device_id`) | INPUT |
| 经度 | `rule_variable.id = 73` (`gps_longitude`) | INPUT |
| 纬度 | `rule_variable.id = 74` (`gps_latitude`) | INPUT |
| 期数 | `rule_variable.id = 76` (`period`) | INPUT |
| 金额 | `rule_variable.id = 77` (`amount`) | INPUT |
| 决策结果 | `rule_variable.id = 141` (`result`) | OUTPUT |

系统默认只通过稳定 ID 建立引用，不通过变量编码、名称或标签运行时回溯匹配。加载时必须验证引用存在、作用域可用于目标项目且类型适合对应指标；引用失效时，该指标返回明确配置错误，不静默猜测其他变量。

用户可选择变量或数据对象字段。持久化项包含：

- `metricField`：固定枚举；
- `refType`：`VARIABLE` 或 `DATA_OBJECT_FIELD`；
- `refId`：被引用记录 ID；
- `jsonSource`：`INPUT` 或 `OUTPUT`；
- `decisionValues`：仅决策结果使用，包含通过、人审、拒绝的值集合。

### 5.2 决策默认值

当前数据同时存在 `result` 枚举值和决策常量值，系统默认兼容两套历史口径：

- 通过：数字或字符串 `0`、`100`、`PASS`；
- 拒绝：数字或字符串 `1`、`101`、`REJECT`；
- 人审：数字或字符串 `2`、`102`、`REVIEW`。

字符串比较去除首尾空白并忽略英文大小写，不对其他业务文本做模糊匹配。用户可以在设置页添加或删除精确取值。

### 5.3 存储与回落

复用现有 `console_user_preference`，新增偏好键 `DASHBOARD_MAPPING`，避免为用户偏好重复建表。偏好 JSON 使用 `schemaVersion = 1`，包含个人默认映射和以项目 ID 为键的项目覆盖映射。

每个字段独立回落：

1. 当前用户、当前项目的字段覆盖；
2. 当前用户的个人默认字段；
3. 系统默认字段。

设置页支持单项“恢复继承值”，删除对应覆盖，不修改变量本身。控制台登录关闭时没有可靠的用户身份，后端只使用系统默认映射，设置页以只读方式说明原因。

## 6. 指标口径

### 6.1 进件去重

进件唯一键按以下顺序生成：

1. 映射后的非空进件编号；
2. 非空 `trace_id`；
3. `rule_execution_log.id`。

项目编码是唯一键的一部分，因此不同项目的相同进件编号分别统计。同一项目同一进件保留筛选范围内 `create_time` 最新、`id` 最大的执行结果。

### 6.2 核心决策指标

- 进件数：去重进件总数，包括执行失败或决策结果缺失的进件；
- 通过数、人审数、拒绝数：最新决策结果落入对应精确值集合的去重进件数；
- 通过率：通过数 / 进件数；
- 人审率：人审数 / 进件数；
- 未分类数：进件数减去通过、人审和拒绝数，不作为顶部主卡，但在决策分布提示中展示；
- 进件设备数：映射后非空设备号的去重数量。

分母为 0 时比率返回 0，同时响应携带 `empty = true`，前端显示 `--` 而不是误导性的 `0.00%`。

### 6.3 期数与金额

- 期数占比：仅使用可转换为非负整数的期数；按进件数降序保留前 7 个期数，其余合并为“其他”，相同进件数按期数升序决定顺序；
- 金额占比：仅使用有限且非负的数值；固定使用 `[0,1000)`、`[1000,3000)`、`[3000,5000)`、`[5000,10000)`、`[10000,30000)`、`[30000,50000)`、`[50000,100000)`、`[100000,+∞)` 八个业务区间；
- 两个图表均同时返回数量、占比、有效样本数和被排除样本数。

### 6.4 地图热力图

经纬度只在读取后的聚合副本中校验：

- 必须能够转换为有限数字；
- 经度必须在 `[-180, 180]`；
- 纬度必须在 `[-90, 90]`。

无效坐标不进入热力图，但原始 `input_params`、`output_result` 和日志行完整保留。响应返回有效点数、未入图记录数和按原因统计的排除数量。有效坐标的经纬度分别四舍五入到小数点后 2 位并按网格计数后返回，避免把逐笔明细发送到浏览器。

### 6.5 规则执行耗时

使用 `rule_execution_log.execute_time_ms`，排除空值和负数，按 `<50ms`、`50–99ms`、`100–299ms`、`300–499ms`、`500–999ms`、`≥1000ms` 分布，同时返回平均值、P95 和 P99。

### 6.6 数据库、名单和外数

- 数据库数据源个数：有权限范围内的总数和启用数；
- 数据库查询时效：`module_type = DATABASE` 的调用数、成功率、平均耗时、P95、P99；
- 名单分类个数和占比：启用名单库按 `list_type` 分组；
- 名单查询时效：`module_type = LIST` 的调用数、成功率、平均耗时、P95、P99；
- 上游数据源 API 个数：启用数据源下启用 API 的数量；
- 上游数据源查询时效：`module_type = DATASOURCE`、`action_type = API_INVOKE` 且 `provider_request = 1` 的调用数、请求成功率、查得率、平均耗时、P95、P99；缓存命中但未实际请求上游的记录不计入上游耗时；
- 下游项目规则个数：项目级已发布规则与项目绑定的已发布全局规则去重后的数量。

### 6.7 账单调用

- 请求数、查得数和查得率使用外数运行日志中的真实上游请求与 `found` 标记；
- 计费总额使用相同项目和时间范围内 `rule_billing_record.amount` 汇总；
- 多币种不直接相加，按币种分别返回。只有单一币种时才展示一个总额；多币种时展示分币种明细；
- 账单记录与运行日志不做脆弱的逐行推测关联，两个来源分别按统一项目和时间范围聚合，并在页面标明各自口径。

### 6.8 规则集 TOP 与审批

- 规则集命中 TOP 复用现有追踪解析口径；每行展示进件数 `evaluationCount`、命中数 `hitCount` 和命中率 `hitRate`；按命中数降序、进件数降序、规则编码升序取前 10；
- 规则审批分布统计 `resource_type IN (RULE, RULE_PROJECT_BINDING)`，按 `EDITING`、`PENDING`、`APPROVED`、`REJECTED`、`CANCELLED`、`CONFLICT` 分组。

## 7. API 设计

统一前缀：`/api/rule/dashboard`。

- `GET /applications`：进件核心指标、期数、金额和地图；
- `GET /operations`：耗时、数据库、名单、外数、下游规则和账单；
- `GET /governance`：规则集 TOP 和规则审批；
- `GET /settings?projectId=`：返回解析后的有效映射、各字段来源和可编辑覆盖；
- `PUT /settings?projectId=`：保存个人默认或项目覆盖；
- `DELETE /settings/{metricField}?projectId=`：恢复单项继承值。

三个统计接口共享参数：

- `projectId`：可空；空表示全部可见项目；
- `startTime`、`endTime`：格式 `yyyy-MM-dd HH:mm:ss`；
- 未传时间时服务端使用当前日期前 6 天 `00:00:00` 到查询时刻；范围跨度超过 90×24 小时返回 400；开始时间晚于结束时间返回 400。

服务端不能信任前端权限裁剪。登录启用时，从 HttpSession 取得用户 ID，并根据有效权限分别决定是否查询和返回各模块；登录关闭时沿用现有“不强制权限”的行为。

## 8. 权限裁剪

数据看板本身对已进入控制台的用户可见，具体区域按现有权限裁剪：

| 区域 | 所需权限 |
|---|---|
| 进件、执行耗时、规则集 TOP、下游规则 | `rule:view` |
| 数据库数量与时效 | `database:view` |
| 名单分类与时效 | `field:view` |
| 外数 API 数量、时效、查得情况 | `datasource:view` |
| 账单金额 | `project:view` |
| 规则审批分布 | `approval:view` |

无权限区域不查询、不返回明细数据。响应只返回 `visible = false`，前端直接隐藏该区域。全部区域均不可见时，页面显示权限空状态并保留账户退出等基础操作。

## 9. 查询与索引

### 9.1 查询原则

- 时间条件必须下推到数据库，利用执行日志分区裁剪；
- 查询只选择指标需要的列，禁止加载大体积 `trace_info` 给不需要追踪的统计；
- 动态 JSON 取值先检查 `JSON_VALID`，再使用由服务端引用解析器生成的安全路径；
- 全项目查询使用用户权限允许的模块范围，现有系统没有项目级 ACL，因此不伪造不存在的项目授权；
- 地图只返回网格聚合，不返回进件编号、设备号或逐笔坐标；
- 统计查询只读，不调用任何更新日志的方法。

### 9.2 候选索引

实施时先对实际 SQL 执行 `EXPLAIN`，仅在现有索引不能覆盖查询前缀时增加以下候选索引：

- `rule_execution_log(create_time, project_code)`：全项目时间范围统计；现有 `(project_code, create_time)` 继续服务单项目查询；
- `rule_runtime_call_log(project_id, module_type, action_type, create_time)`：项目、模块、动作和时间聚合；
- `rule_billing_record(project_id, occur_time, currency)`：项目时间范围内分币种金额聚合；
- `governance_approval_request(project_id, resource_type, status, create_time)`：规则审批分布；
- `rule_definition(project_id, status, scope)`：项目已发布规则计数；
- `rule_definition_ref(project_id, definition_id)`：项目绑定全局规则去重。

若 `EXPLAIN` 证明已有索引已覆盖，则不新增对应索引。SQL 结构测试必须校验新增索引和初始化脚本一致。

## 10. 前端信息架构

### 10.1 看板页

页面使用现有间距、字体、颜色和主题变量，按以下层级组织：

1. 页面标题、最后刷新时间和“看板设置”入口；
2. 公共筛选区：项目、快捷时间、自定义时间、查询、重置、刷新；
3. 核心指标卡：进件数、通过数、人审数、拒绝数、人审率、通过率、进件设备数；
4. 业务分布：期数占比、金额占比、进件地图热力图；
5. 运行资源：规则耗时分布、数据库、名单、外数和下游规则；
6. 经营治理：账单调用、规则集 TOP 和审批分布。

桌面端使用 12 列 CSS Grid；窄屏按业务组顺序降为单列。卡片标题、口径说明、数值和单位使用一致层级；数值按右对齐和等宽数字特性展示。颜色不能作为唯一状态信息，图例同时包含文本与数值。

图表统一使用 Apache ECharts `6.1.0`，不再引入 AntV、Vue 图表包装库或第二套地图运行时。通过 `echarts/core` 按需注册柱状图、饼图、热力图、地图及其实际使用的组件，只引入热力图所需的 Canvas 渲染器；禁止从 `echarts` 入口全量导入。所有图表复用一个轻量封装组件，统一处理初始化、响应式尺寸、加载、空状态、销毁和可访问性说明。

图表颜色不维护固定品牌色，而是在渲染时从现有主题 CSS 变量读取主色、辅色、明暗色阶、语义色、文字色、分隔线和背景色，生成看板调色板。普通分类序列优先使用主色与辅色的明暗色阶，成功、警告、拒绝等业务语义才使用对应语义色；图例、标签和数值同时表达状态，不能只靠颜色区分。图表监听现有 `tianshu-theme-change` 事件，在主题色、浅色/深色模式或色弱模式变化后重新应用主题选项，不要求刷新页面，也不把用户主题复制到看板设置或浏览器会话缓存。

地图采用经过项目审查的标准地图边界数据，GeoJSON 作为本地静态资源随前端发布并保留来源和审图信息，不依赖外网、密钥或第三方瓦片服务。

### 10.2 设置页

设置页提供“个人默认”和“指定项目覆盖”范围切换。每个映射行展示：

- 指标名称和用途；
- 输入/输出来源；
- 变量选择器；
- 当前生效来源标签；
- 对应的系统默认值；
- 单项恢复继承操作。

决策结果区域额外配置通过、人审、拒绝的精确值标签。保存前校验：引用存在、类型兼容、项目作用域可用、三个决策集合互不重叠。校验失败时保留用户输入并定位到具体字段。

## 11. 加载、空状态与错误处理

- 三个统计分区独立显示骨架屏；
- 查询返回无样本时显示“当前筛选范围内暂无数据”，不绘制伪造的零值图；
- 字段映射失效只影响依赖该字段的指标，并提供进入设置页的修复入口；
- 单个分区请求失败时显示错误摘要和“重试本区域”；
- 地图展示有效点数与未入图记录数，未入图原因通过提示查看；
- 后端日志记录统计异常，但不得把原始进件 JSON 或坐标写入错误消息；
- 统计超时返回明确错误，不回退到不受时间限制的全表扫描。

## 12. 安全与隐私

- 映射保存接口只能操作当前 Session 用户自己的偏好；客户端不能提交其他用户 ID；
- 项目覆盖只接受现有项目 ID；
- 后端严格校验 `refType`、`refId`、字段类型和 JSON 来源；
- 看板响应不返回进件编号、设备号、原始请求、原始响应或逐笔坐标；
- 原始日志表保持现有留存策略，本功能不改变其内容和生命周期；
- 地图及所有图表只使用聚合值。

## 13. 测试与验收

### 13.1 后端

- 字段映射三级回落、单项删除和失效引用；
- 决策两套默认值、未知决策和零分母；
- 进件去重与最新结果选择；
- 金额、期数的非法值排除和分桶边界；
- 经纬度空值、NaN、Infinity、越界值排除，且验证原日志对象和数据库行不被修改；
- 数据库、名单、外数、账单、规则集和审批口径；
- 多币种账单不相加；

- SQL 初始化及索引结构测试。

### 13.2 前端

- 默认路由、登录回跳、工作区兜底和侧栏选中状态；

### 13.3 完整验证

前端按仓库要求依次执行开发服务页面验证、`npm test`、`npm run lint`、`npm run build` 和相关 Playwright 烟测；后端依次执行 `mvn clean install -DskipTests`、启动 `rule-engine-server` 验证、`mvn test`。长期服务使用 30 分钟工具超时并在验证后主动停止。

浏览器验收必须从登录或控制台进入页开始，通过页面筛选、设置保存、项目覆盖、地图无效坐标提示、局部错误重试等完整 UI 流程操作，不通过后端直接造数据跳过页面步骤。

## 14. 发布与兼容

- 新增路由不删除 `/project`，旧书签继续有效；
- 现有日志和配置表数据无需改写；
- 新增索引通过 `schema.sql` 的幂等增量同步方式覆盖新旧数据卷；
- 用户没有 `DASHBOARD_MAPPING` 偏好时自动使用系统默认；
- 单个默认变量 ID 不存在时，设置响应明确标记缺失，依赖指标不执行错误猜测；
- 任何历史无效 JSON、无效坐标或未知决策值只计入数据质量提示，不阻断其他有效样本。
