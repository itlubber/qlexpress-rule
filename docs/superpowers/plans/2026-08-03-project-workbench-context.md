# 项目工作台与项目上下文实施计划

日期：2026-08-03

## 目标

把现有项目详情升级为面向业务人员的工作台，通过后端统一返回项目就绪度、配置数量、待审批和最近运行摘要；从工作台进入变量、外数、模型、规则、测试、审批和日志后，页面持续显示并使用同一个项目上下文。一级菜单继续平铺，侧栏继续仅按拖拽宽度自动切换显示形态。

## 设计决策

- 采用独立 `ProjectWorkbenchService` 聚合数据，避免继续膨胀已有 `RuleProjectService`。
- 统计项目自有资源；规则统计同时包含项目规则和已经通过审批绑定到项目的全局规则。
- 数据来源、模型没有配置时标记为“可选”，不阻断只使用输入字段和可视化规则的项目。
- 项目、字段、规则、测试场景、审批、发布和运行按真实状态生成动态检查项；每项返回状态、原因和下一步动作编码。
- 非关键统计失败只使对应指标显示不可用并返回警告，不让整个工作台空白。
- 项目上下文通过显式 `projectId` 路由参数进入模块，同时保存到当前浏览器会话；它只影响筛选和表单默认值，不替代后端权限及归属校验。
- 没有项目上下文时，规则、变量、对象、字段校验和实验的新建表单必须显式选择范围或项目，禁止默认创建全局资源或默认选择第一个项目。

## 任务一：后端项目工作台聚合接口

1. 先新增 `ProjectWorkbenchServiceTest`，覆盖项目停用、缺少字段、规则未发布、存在待审批、已有发布和最近运行等状态组合。
2. 新增 `ProjectWorkbenchDTO`，包含项目摘要、指标、动态检查项、最近 24 小时运行摘要、最近一次执行和降级警告。
3. 新增 `ProjectWorkbenchService`，按项目 ID 聚合变量、外数/数据库数据源、模型、项目可用规则、测试场景、待审批和执行日志。
4. 在 `RuleProjectController` 增加 `GET /api/rule/project/{id}/workbench`。
5. 为聚合服务和控制器补充定向测试。

## 任务二：前端项目上下文基础能力

1. 先新增项目上下文工具和组件测试，覆盖会话恢复、路由参数优先、项目切换、退出上下文以及只在业务模块展示。
2. 新增 `projectContext` 工具，集中处理项目 ID 规范化、会话读写、上下文路由识别和查询参数合并。
3. 复用 Vuex 的 `currentProject`，在 mutation 中同步会话缓存。
4. 新增 `ProjectContextBar`，展示当前项目名称与编码，支持切换项目、返回工作台和退出项目范围。
5. 在 Layout 中监听显式 `projectId`，加载真实项目信息；侧栏导航到支持项目上下文的模块时保留项目 ID。

## 任务三：项目详情升级为工作台

1. 先扩充 `projectDetail.spec.js`，覆盖工作台加载、失败降级、动态动作路由和项目上下文写入。
2. 新增 `ProjectWorkbenchOverview` 组件，按“当前最重要动作 → 就绪检查 → 关键统计 → 快捷入口 → 最近运行”的层级展示。
3. `ProjectDetail.vue` 并行加载项目、工作台和规则清单；工作台失败时规则清单仍可使用。
4. 保留原有规则筛选、设计、生命周期、关联全局规则和删除审批能力，放入明确的“项目规则”区域。
5. 删除项目列表顶部静态八步说明，项目列表只负责项目检索和进入工作台。

## 任务四：业务页面应用项目上下文

1. 规则列表在项目上下文中查询项目可用规则，新建规则默认项目级；无上下文时作用范围为空并要求显式选择。
2. 变量页将上下文同步到变量、对象、常量和字段校验筛选；新建资源默认当前项目；无上下文时不默认全局。
3. 模型、外数和规则测试页面读取 `projectId` 并筛选数据，新建资源默认当前项目。
4. 审批列表传递后端已支持的 `projectId` 条件；执行日志按当前项目的稳定项目编码筛选。
5. 新建分流实验优先使用显式项目上下文；无上下文时保持项目为空，不再默认第一个项目。

## 任务五：验证与浏览器验收

1. 运行项目工作台和项目上下文定向前后端测试。
2. 运行 ESLint、前端构建、`mvn clean install -DskipTests`。
3. 在独立端口启动后端和前端，验证服务正常。
4. 浏览器从项目列表进入工作台，检查动态状态和快捷入口；依次进入变量、规则、模型、测试、审批和日志，确认项目上下文一致。
5. 浏览器在有上下文时检查新建默认项目，在退出上下文后检查必须显式选择范围或项目。
6. 运行前后端全量测试，停止本轮验证进程，复核差异并提交。

## 完成标准

- 工作台不再显示静态通用步骤，而是展示当前项目真实状态、阻塞原因和可执行下一步。
- 项目上下文通过项目 ID 传递，页面不根据名称或编码猜测资源归属。
- 业务人员从工作台进入各模块后始终能看到当前项目，筛选和新建默认值一致。
- 离开项目上下文后不会因为默认全局或默认第一个项目而误建资源。
- 原项目规则管理能力和既有审批链路保持可用。
- 前后端测试、构建、服务启动和真实浏览器验收全部通过。
